## Overview

Portfolio Website v1 was the first version of my personal portfolio website.

It was built with Next.js and Tailwind CSS to present my frontend development background, selected skills, and professional profile in a simple online format.

This version also included a contact form powered by Nodemailer, making it possible for visitors to send messages directly from the website.

## Problem

The previous portfolio helped establish an online presence, but it was still limited in how it presented my work.

It focused more on basic profile information rather than showing deeper technical decisions, project context, architecture thinking, and real product workflow.

For a stronger frontend portfolio, I needed a better structure to explain not only what I built, but also why and how I built it.

## Goal

The goal of Portfolio Website v1 was to create a simple and accessible personal website that could introduce my frontend development profile.

It needed to communicate:

- who I am
- what frontend skills I use
- what kind of work I have experience with
- how people can contact me
- a basic online presence for professional opportunities

## Core Features

- Personal introduction section
- Frontend skills presentation
- Work background overview
- Contact form
- Email delivery using Nodemailer
- Responsive layout
- Public deployment on Netlify

## Architecture

The website was built as a simple portfolio site using Next.js for page structure and Tailwind CSS for styling.

The contact flow used Nodemailer to send form submissions through email, allowing the portfolio to support a real contact interaction instead of only showing static contact links.

Key decisions:

- Next.js for portfolio page structure
- Tailwind CSS for responsive styling
- Nodemailer for contact form email delivery
- simple page structure
- lightweight deployment
- clear personal branding

## UX Decisions

The design focused on making the portfolio easy to read, easy to navigate, and easy to contact from.

Important UX decisions:

- keep the layout simple
- make the content easy to scan
- present skills clearly
- provide a direct contact form
- avoid unnecessary complexity
- make contact information accessible

## Challenges

The main challenge was creating a portfolio that represented my frontend background clearly while keeping the scope small.

As the first version, it helped validate what information should be included, but it also showed what needed to be improved in the next iteration.

Some limitations became clear:

- project presentation needed more depth
- case studies were not strong enough
- technical decision-making was not clearly shown
- product thinking was not visible enough
- the content hierarchy could be stronger

## Result

Portfolio Website v1 became the foundation for the current portfolio rebuild.

It helped establish my online presence with a working contact flow, but the next version improves the positioning by focusing more on case studies, frontend architecture, product thinking, and real project storytelling.

The current Astro portfolio is a more refined version built to present my work with stronger clarity, structure, and professional impact.
